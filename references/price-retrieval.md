# 互动询价与近期市场参考价

## 对话顺序

| 已知情况 | 下一步 |
| --- | --- |
| 文字已提供价格、单位和地区，或照片价签可读 | 直接使用，不重复询价；缺少的信息一次问清 |
| 只有水果名或无价签照片 | 先询问价格、计价单位和缺少的城市，等待回复；营养查询可以同时进行 |
| 用户已说不知道价格/没看价格/要求代查 | 不重复问价格；地区已知则直接搜索，地区不明只问城市或国家 |
| 用户不知道价格，但拒绝提供地区 | 说明本地参考价无法确定；用户明确接受全国口径时可搜索全国参考并标明范围，不能自行挑城市 |
| 用户只看营养/不想联网 | 不再追问，提供有来源的营养资料，暂不生成价格排名 |

使用宿主可用的互动组件或普通聊天。一次只问缺少的信息，支持用户直接填价格或回复“不知道”。不要在尚未收到回复时推定用户不知道；不要要求用户配置 API。当前 Python CLI 不负责聊天交互或搜索网站；由 Agent 执行询问、检索和证据录入。

示例问法：“香蕉多少钱一斤/公斤？在哪个城市买的？不知道价格也可以，我来查近期参考价。”若城市已知则省去城市问题。多水果场景一次询问缺价的品种，不逐个打断。

## 用户不知道时的联网检索

1. 使用明确的城市/地区、鲜果品种及相对当前日期的时间范围搜索；优先**最近7天**，按实际报价日期比较新旧，不能只看搜索结果排序或网页抓取日期。
2. 优先当地政府价格监测中的**零售**条目、当地可购买的商超/电商商品页面；实际打开页面核对。记录机构/商家、报价日或统计周期、城市、品种等级、包装净重、币种、计价单位和来源URL。不凭搜索摘要生成数值。
3. 有多个来源时优先同城、相近规格和近期普通零售价，不挑最低促销价制造冠军。会员券、满减、最低购买量、配送费、售罄和起批量需说明；不能确定到手价时不称其为实际可购价格。
4. 把来源公布的代表价或均价作为单值；只给范围时保留上下限，可分别做低价/高价情景，不默取中点。多品种比较尽量统一地区、时间和零售口径。
5. 找不到近7天数据时，可以继续寻找最近30天的记录，但先展示日期并询问用户是否接受旧参考，再使用 `--allow-stale`。不得静默放宽期限、换城市或把旧报价的 `observed_on` 改成查询当天。
6. 如果只有批发/产地收购价，明确给出“批发参考价”及日期、市场、起批条件和链接。它可以帮助了解行情，**不能默认填入零售价格模型**，也不能以未知加价率猜零售价。仍可给营养结论或说明缺少可比零售价。
7. 无联网能力、打不开来源或搜不到可核验结果时直接说明，并保留用户补价入口；不自动使用模拟价。

## 录入与计算

使用 `data/prices.reference.template.json`，将核验数值填写后另存 `data/prices.local.json`。模板中的零金额和日期占位符不是真实数据，不可直接用于计算。

| 字段 | 要求 |
| --- | --- |
| `kind` | `reference_retail`，与 `retail` / `user_receipt` / `simulation` 区分 |
| `fruit_id` | 营养目录已有的匹配水果 ID |
| `amount_cny`、`measure` | 实际读到的人民币金额与 `kg` / `jin` / `pack` 单位；中国市斤=500g，不把其他地区的“斤”直接套用 |
| `package_kg` | `pack` 时必填净重；其他币种不能直接填人民币字段，需有日期及汇率证据另行换算 |
| `observed_on` | 原始报价日或统计期末日；完整统计周期写在备注中，不用访问日期替代 |
| `location` | 报价所对应的城市/覆盖地区，不能伪装成用户实际门店 |
| `source_url` | 可打开的原始 HTTP(S) 来源，必填 |
| `source_note` | 零售口径、品种/规格、原始单位、统计周期或商品限制、查询日期；必填 |

```bash
python -m fruit_optimizer --prices data/prices.local.json validate
python -m fruit_optimizer --prices data/prices.local.json profile 香蕉
python -m fruit_optimizer --prices data/prices.local.json --format md rank 钾
```

`reference_retail` 不需要 `--allow-simulation`，因为有实际公开来源；它仍是参考价，不能宣称为用户实际成交价。程序检查必填证据、日期和数值；来源是否真实、属于零售及品种是否匹配，仍需宿主实际核对。

## 输出要求

每个参考价格同时给出**金额与单位、地区、报价日期、来源链接和参考性质**。先声明“以下用近期市场零售参考价估算，实际以购买时为准”，再给每元营养、替代或预算结果。混合用户报价与参考价时逐项标明；用户后来给出实际价格时覆盖对应参考价并重新计算。若仅部分候选有有效价格，说明参与排名的数量，不补造其他价格。
